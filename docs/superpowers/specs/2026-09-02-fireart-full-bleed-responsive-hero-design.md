# FireArt Full-Bleed Responsive Hero Design

## Objective

Make the existing FireArt homepage hero and its first gallery scene read at the intended visual scale on every normal CSS viewport, from narrow phones to 32:9 monitors. The video must cover the complete hero without a blurred frame, letterbox, stretched imagery, or cropped baked-in typography. The existing visual identity, copy, footage order, animation rhythm, navigation, and page structure remain unchanged.

## Confirmed Direction

Use six aspect-family hero exports authored from the existing HyperFrames landscape and portrait projects. Each export is full-bleed and keeps its baked typography and primary formation inside an aspect-specific safe area. Do not derive uncommon ratios by placing a sharp frame over a blurred copy of the same frame.

The browser continues to select the closest export by CSS viewport aspect ratio. It must not use physical display resolution or device-name checks.

## Root Cause

The current HTML video element already fills the hero and uses `object-fit: cover`. Several delivered media variants were nevertheless generated by containing the sharp master inside the target canvas and filling the remaining pixels with a blurred enlargement. That blurred frame is permanently encoded in the MP4 and WebP poster, so CSS cannot remove it.

The first gallery has a separate scale problem. Its viewport is capped by the global `90rem` content width, so a half-scene card stays roughly `45rem` wide even on 2K, 4K, and 32:9 CSS viewports. The result is technically centered but visually microscopic.

## Video Architecture

### Source projects

- Landscape source: `tmp/fireart-drone-fireworks-trailer-20s-hf`
- Portrait source: `tmp/fireart-drone-fireworks-trailer-20s-mobile-hf`
- Preserve the current 20-second loop, scene order, timing, typography, transitions, and near-black loop endpoints.
- Replace blurred contain framing with authored full-bleed framing. Use scene-specific `object-position` and scale values so the critical drone formation or fireworks burst remains visible.
- When a landscape photograph cannot survive a portrait crop, use the existing portrait asset for that scene. Do not synthesize imagery or add a decorative replacement background.

### Delivered aspect families

| Variant | Target pixels | Intended CSS viewport family | Source composition |
| --- | ---: | --- | --- |
| `wide` | 1920×1200 | landscape ratios from 1.50 up to 2.00 | landscape |
| `ultrawide` | 1920×900 | landscape ratios of 2.00 and wider | landscape |
| `tablet-landscape` | 1440×1080 | landscape ratios above 1.00 through 1.50 | landscape, with tablet-safe typography |
| `tablet-portrait` | 1080×1440 | portrait ratios from 0.60 through 1.00 | portrait, with tablet-safe typography |
| `mobile` | 900×1600 | portrait ratios above 0.50 and below 0.60 | portrait |
| `mobile-tall` | 900×1950 | portrait ratios of 0.50 and narrower | portrait |

Every pixel of every target canvas must come from a sharp, intentionally framed photograph, animation layer, or the composition's intentional near-black title/loop frame. No blurred edge-fill, duplicate backdrop, side pillar, top/bottom band, or soft `contain` canvas is allowed.

### Typography safety

- Baked video titles must remain fully visible in all six exports with at least 5% horizontal and 4% vertical safe space.
- The website's live hero copy remains separate from the video. It must use fluid `clamp()` sizing and a centered content stage that grows on large viewports without becoming edge-to-edge on ultrawide screens.
- The live copy and baked copy may overlap only where the current art direction intentionally does so; neither may be clipped by the viewport.

### Web delivery

- Keep MP4/H.264, 30 fps, muted autoplay, looping playback, `playsInline`, and static WebP posters.
- Add `faststart` metadata.
- Keep the wide and ultrawide MP4s at or below 9 MB each and the other variants at or below 6 MB each unless a lower size causes obvious block artifacts in the drone lights or typography.
- Keep the current visibility, orientation-change, viewport-resize, and back-forward recovery behavior in `HeroVideo.jsx`.
- Keep `object-fit: cover`; remove the CSS blurred poster layer because full-bleed media makes it unnecessary.
- Reduce only the excessive blur/darkening directly around the media. Preserve the contrast gradients required to keep the live hero copy readable.

## Gallery Scale Architecture

The global readable-content cap remains unchanged for ordinary sections. The pinned cinematic gallery receives its own fluid stage cap:

```css
width: min(100%, clamp(90rem, 72vw, 160rem));
```

The gallery continues to calculate motion from its measured CSS width. Cards remain half-stage panels on desktop and full-stage panels on compact/coarse-pointer layouts. Image height, headings, labels, and spacing gain fluid upper bounds based on `vmin`/`clamp()` so they grow perceptibly on 2K, 4K, and ultrawide CSS viewports without overflowing short 32:9 screens.

The layout must preserve one continuous pinned horizontal sequence, avoid horizontal document overflow, and recalculate after resize, orientation change, and `visualViewport` changes.

## Hero-to-Gallery Handoff

Keep the existing pause-without-detach video lifecycle. The final hero pixels and the first gallery background must meet through a short color-matched gradient, with no layout jump, black flash, source reset, or scroll stall. The transition overlay must not be used to hide a badly framed video.

## Verification

### Automated checks

- Add a failing regression check before changing production CSS or React behavior.
- Assert that each viewport family selects the expected source and poster.
- Assert that the video box matches the hero box, uses `object-fit: cover`, and has no active blurred backdrop layer.
- Assert that the cinematic gallery stage grows beyond `90rem` on large CSS viewports, respects the `160rem` cap, and never creates document-level horizontal overflow.
- Re-run hero lifecycle, navigation, gallery motion, and orientation-change tests.
- Run the production build.

### Media checks

- Validate dimensions, duration, codec, frame rate, and file size with FFprobe.
- Extract temporary contact-sheet frames from each export at representative photo and title moments.
- Inspect the outer 15% of all four edges for blurred duplicate fill, bars, clipping, or stretched pixels.
- Confirm baked typography is complete at every sampled title moment.
- Delete all extracted audit frames after review.

## Scope Boundaries

- Do not redesign unrelated sections or routes.
- Do not change copy, colors, package content, navigation structure, or animation timing.
- Do not introduce device-specific JavaScript checks or a list of per-device media queries.
- Do not scale the whole application with `transform`, `zoom`, or a fixed design-canvas ratio.
- Do not use subagents for this implementation.
